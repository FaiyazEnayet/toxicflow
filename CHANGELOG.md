# Changelog

## [Unreleased]
### Docs
- Centered the README header: uniform dark badge labels and three action buttons in the dashboard palette (Open Demo, Explore Method, Run Locally).

### Added
- Recoverable raw event journal (Stage 3 TF3): a recording session now also writes an append-only journal of the raw market events under `journal/` in the session directory, so a session can be replayed exactly instead of being reconstructed from touch quotes alone. Records are typed (`JournalRecord`: session start/end control records, snapshots, depth updates, trades, and overflow records) and each carries a session id plus a sequence number and an FNV-1a checksum over its canonical payload. Only events the sync machine commits are journaled: a snapshot record marks each successful merge (the recovery boundary), applied depth updates and recorded trades follow in order, and a failed merge journals nothing. Records accumulate into fixed-size Arrow batches (512 per batch in live sessions) behind a bounded pending queue (16 batches); batches flush as segment files (`seg-NNNNNN.parquet`) written to a temporary name, synced, and renamed into place, so a process killed mid-session loses only the batch still in memory and every completed batch survives. When the sink cannot keep up, the buffer stays at its bound (8,704 records live) and dropped records are counted and written into the journal as an explicit overflow record rather than lost silently. `replay_journal` reads a journal back in segment order and validates it before returning anything: sequence numbers contiguous from zero, one session id throughout, kind column matching each payload, and every payload matching its stored checksum; incomplete `.tmp` segments are ignored. Replay folds the records into a digest (`journal_digest`) that is stable across replays of the same journal. New fixtures: replay digest determinism with exact record round-trip, forced termination preserving exactly the two completed batches, a slow sink fed 100 records against a 12-record bound (88 drops, one overflow record), a tampered payload rejected on checksum, and the recorder journaling committed events only. Test count: 110 -> 115. No version bump.

- `MmReport` now carries `seconds_scored` and a per-second `decisions` vector (`MmDecision`: second, decision timestamp, latest observed quote timestamp, VPIN value plus VPIN completion timestamp, gated flag, gated-leg fills), so every scored decision's causal inputs are auditable from the report alone.
- Per-fold model persistence and an exact prediction ledger (Stage 3 N4): `predict::walk_forward_detailed` returns what `walk_forward` always computed in memory and threw away: each fold's fitted coefficients, its train/test geometry, and every out-of-sample probability. The export now writes `experiments/<run>/fold_models.json` and `experiments/<run>/predictions.csv` next to the existing files. Each fold record carries the intercept plus the 5 raw-space weights, the preprocessing schema (feature names and order, feature version, how the fold standardization is folded into the raw-space weights, fit hyperparameters), the training cutoff (row count and bar timestamp), the purge gap, the fold's train majority rate, and SHA-256 input hashes over the dataset rows and over the fold's training rows (canonical bit-pattern encoding; the in-tree SHA-256 is pinned by FIPS known-answer fixtures). The ledger holds one timestamped row per evaluated bar (fold, dataset row index, bar time, the 5 feature values, target, probability); dataset rows now carry their bar start time (`Bar.time_ms`) to make that possible. An independent loader (`load_fold_models`, `load_predictions`, `verify_prediction_ledger`) reads only the two files and reconstructs every prediction: on the archived 3.25h BTCUSDT session (1,044 dataset rows) it reproduces all 832 out-of-sample rows (4 folds x 208) with a maximum probability error of 2.2e-16 against the 1e-8 bar, the recomputed accuracy (0.791) and Brier score (0.1487) match the saved report, and the row counts sum exactly to the saved denominator; the evaluation numbers themselves are unchanged from the in-memory computation (accuracy 0.791 against the 0.786 majority baseline, the N2 figures). Fold geometry is enforced at load time: each test block must start exactly `purge` bars after its training cutoff, so no evaluated row was trained on. Coefficients from runs before this serialization existed were held in memory only; `fold_models.json` labels them `UNRECOVERABLE` and no historical checkpoint recreation is claimed. The loader verifies the saved artifacts against each other; re-verifying the training inputs themselves still requires the recorded session, whose hash is pinned in the file. Test count: 91 -> 98. No version bump.

### Fixed
- Transactional book sync (Stage 3 E2): the recorder and the live dashboard no longer carry separate copies of the snapshot/diff sync procedure, and neither can change state before validation finishes. Both now drive one shared state machine (`src/booksync.rs`). Depth events and snapshots are typed values validated at parse time (finite prices > 0, quantities >= 0, update ids in range); the previous `unwrap_or(0.0)` fallbacks in `recorder.rs` and `main.rs` are gone, so a malformed price, quantity, or id is rejected with a diagnostic instead of being applied as a zero level. A snapshot merge builds a candidate book plus a candidate quote buffer and commits both only after every buffered event applies cleanly and the result is not crossed; previously `merge_snapshot` loaded the snapshot into the live book, emitted a quote per applied event, and only then discovered a mid-buffer gap, leaving a half-applied book and emitted quotes behind. A diff that would cross the synced book, an out-of-order arrival, and a redelivery of an applied update-id range carrying different content are all classified as gaps with an explicit diagnostic (the triggering event is kept as the resync buffer head); duplicate redelivery is idempotent and stale events are ignored. The event buffer is bounded at 4,096 with the overflow recorded. The dashboard's stall is fixed by the same machine: while unsynced it now restarts a snapshot fetch whenever none is in flight, so a snapshot that predates the buffered stream is retried with a fresher one instead of never being re-requested. New fixtures drive captured events through both paths and against the independent replay oracle: a failed mid-buffer merge leaves book and quote count unchanged, crossed snapshot/diff sequences never sync, a stale snapshot is a visible refetch, and record and live agree on the committed book after every step. Test count: 98 -> 110. No version bump.

### Fixed
- Prediction feature numerics (Stage 3 N1): `rolling_mean_sd` no longer uses sliding sums of squares (E[x^2] - E[x]^2). Each trailing window is computed independently with a two-pass mean-subtracted sum of squares, and a bit-identical window yields sd exactly 0. On the archived 3.25h BTCUSDT session the bar spread is an economically constant one tick (two f64 values near 0.01 differing at the 1e-12 level), and the old formula turned that into spread z-scores in [-14.07, +9.70] with 293 of 1,167 rows beyond |z| = 5 (legacy sd sat in (0, 1e-9) on 671 bars: pure cancellation residue). After the fix the same rows give z in [-3.89, +3.89] with no row beyond |z| = 5. Zero-variance spread windows are flagged explicitly (`Bar.spread_degenerate`, z pinned to exactly 0; 413 of 1,167 archived rows). The feature frame is frozen as `FEATURE_VERSION = "v2"` (v1 = pre-N1), carried on `EvalReport` and in the export summary JSON. Regression fixtures: analytic-variance series under a 1e6 offset (relative error 1.4e-5 before, 2.2e-16 after, against a 1e-10 bar), constant one-tick spread, prefix invariance, finite logistic probabilities. Test count: 69 → 74. No version bump.

### Fixed
- Gap censoring (Stage 3 N2): the recorded session's 920.1-second feed outage is no longer silently interpolated. `metrics::bar_status` reports per-bar observation status and quote age on the OFI bar grid; `predict::build_dataset` censors every supervised row whose trailing feature window or forward target window touches an unobserved bar (feature frame `FEATURE_VERSION = "v3"`); `flow_bars` flags carried and first-post-gap bars and `kyle_lambda` restarts its OLS window inside each segment, never spanning a gap. On the archived 3.25h BTCUSDT session: 91 of 1,174 bars are unobserved; dataset rows go 1,167 -> 1,044; walk-forward accuracy 0.814 -> 0.791 against a majority baseline of 0.809 -> 0.786 (fold std +/-0.4, so no edge is claimed either way; the pre-N2 figures credited the model with rows whose targets crossed the outage); mean Kyle lambda 3.53 -> 2.87 with 65 fewer reported windows. The export summary JSON gains a `gaps` block with the exact denominators. One pre-existing prefix-invariance test now asserts the N2 semantics (an appended post-gap quote adds no rows). Test count: 74 -> 78. No version bump.

### Fixed
- Parquet loader validation (Stage 3 H3): `read_trades` and `read_quotes` now return a typed `StorageError` instead of silently coercing bad records. Null cells, nonfinite prices and sizes, non-positive trade prices and quantities, non-positive quote prices and sizes, negative timestamps, decreasing timestamps, columns whose length does not match the batch row count, and crossed books (bid at or above ask) all fail with the column and row attached; timestamps are required to be non-decreasing, so same-millisecond records still load. Valid records read exactly as before. New fixtures: valid fixture unchanged, null price, NaN price, negative quantity, nonmonotonic timestamps, missing column, crossed book, zero quote size, and inconsistent column length. Test count: 82 -> 91. No version bump.

### Fixed
- Within-calibration lookahead (Stage 3 E1): `run_mm` no longer scores seconds inside the calibration window. TF2 froze the bucket size from a leading 300-second window, but the loop still scored from second 1, so a decision at second 60 depended on trades up to second 300 through the shared threshold. Scored decisions now start at second `calibration_secs`, after the threshold is frozen from fully observed calibration trades; each scored decision is emitted with its decision timestamp, latest observed quote timestamp, and VPIN completion timestamp; `analyze` reports the gated share over scored seconds. On the recorded 3.25h BTCUSDT session (28,224 trades, 106,735 quotes, 11,724.4 s): toy PnL open -11.34 -> -14.51, gated -0.84 -> -3.58, gated 3081/11727 s -> 2995/11427 scored seconds (the old figures included fills from inside calibration that the fixed simulator refuses to score; gating still loses less but remains negative, so no edge is claimed). The TF2 future-trades regression still passes at the fixed code. One pre-existing hand-computed fixture updated with reason (calibration_secs 30 -> 1 so its second-1 fill stays scored while second 0 stays unscored; all expected values unchanged). New fixtures: no scored decision before calibration end, within-calibration edit cannot change already-made decisions (fails pre-fix: VPIN moved at second 6), future suffix cannot change scored decisions or their timestamps, hand-computed scored-after-calibration fixture. Test count: 78 -> 82. No version bump.

### Fixed

### Fixed
- Walk-forward statistics (Stage 3 TF6): the evaluation's headline baseline and its uncertainty figure did not mean what they appeared to mean, and both are repaired in `src/predict.rs`. The old `baseline` was the majority-class rate computed from the test outcomes themselves, so the bar the model had to beat was derived from the answers; it is now the out-of-sample accuracy of a training-majority predictor, where each fold commits to its own training majority label (already recorded per fold by N4) and is scored on that fold's test rows, paired row by row with the model (`WalkForwardDetail::baseline_correct`). The test-outcome rate is still reported, renamed `test_majority_rate` and labeled descriptive-only. `accuracy_std` is now documented as what it always was, the population standard deviation of the per-row 0/1 correctness values (exactly sqrt(acc*(1-acc)) for Bernoulli outcomes), and uncertainty is reported separately as `accuracy_ci`: a moving-block bootstrap over the out-of-sample rows (30-bar blocks matching the rolling feature window, 2,000 resamples, fixed published seed, so an interval is a deterministic function of the rows). Balanced accuracy joins accuracy and Brier in the report and in `fold_models.json` (new saved fields default on load, so pre-TF6 ledgers still verify; the verifier's recomputed accuracy 0.790865 and Brier 0.148746 on the archived session are unchanged). On the archived 3.25 h session the repaired baseline is 0.7861 against accuracy 0.7909, balanced accuracy 0.5358, with a paired-difference interval of [-0.008, +0.023]: no edge, now stated with an interval instead of a bare gap. The two definitions diverge exactly where they should, under regime shift: on the 2026-11-04 capture the training-majority predictor scores 0.4706 while the test-outcome rate claims 0.5294. A multi-session pilot (`predict::evaluate_session` / `summarize_session_pilot`, runner in `examples/tf6_pilot.rs`, report in `docs/tf6_pilot_report.json`) evaluates every independent recording that exists: 5 sessions (the 2026-10-10 session plus the 2026-10-30, 2026-11-01, 2026-11-02 and 2026-11-04 captures; same-night fragments and concatenations of the first session are not counted as independent). Per-session paired differences are +0.005, -0.059, +0.029, +0.044 and +0.074, mean +0.019, with a session-bootstrap 95% interval of [-0.026, +0.056] that includes zero: no demonstrated predictive edge, and the report says so. The pilot is below the 10-session target for generalization claims, the artifact states that in its own notes, and the effective sample unit is the independent session throughout, never the bar count. Known-answer fixtures pin the repaired semantics (a skewed fixture where the training-majority baseline is exactly 0.4 against a test-outcome rate of exactly 0.6, hand-computed balanced accuracy and Brier, bootstrap collapse on constant series). Test count: 110 -> 114. Clippy warning set unchanged (the same four pre-existing test-code warnings). No version bump.

## [v1.2.3] - 2026-10-18
### Fixed
- Connection policy (`src/net.rs`): the recorder no longer assumes an authenticated egress proxy. With no proxy configured it connects directly via TLS; with a proxy URL it tunnels through HTTP CONNECT, accepting both `http://host:port` and `http://user:pass@host:port` forms. A malformed proxy URL is validated once up front and fails fast with an actionable error instead of being retried until the session deadline (`record_session` checks the policy before its retry loop). Credentials are redacted in all log and error output. Regression tests: direct / unauthenticated-proxy / authenticated-proxy fixtures against local endpoints, proxy refusal surfacing, and a fail-fast test proving a bad proxy URL returns immediately rather than burning the deadline.

## [v1.2.2] - 2026-10-18
### Fixed
- `run_mm` no longer peeks at the future: the volume-bucket size is frozen from a leading 300-second calibration window instead of whole-session volume; each second is quoted at the last quote observed strictly before that second starts (second 0 is never quoted); the VPIN gate reads only VPIN completed strictly before the second starts. Appending future trades now leaves earlier bucket thresholds, posted quotes, gate decisions and PnL unchanged. Regression tests: a hand-computed two-trade fixture matching inventory/cash with the decision delay, and a future-trades invariance check (both fail on the old simulation). README toy PnL refreshed on the recorded session: open -11.34, gated -0.84. Test count: 56 → 58.

## [v1.2.1] - 2026-10-18
### Fixed
- `ofi_bars` no longer backfills empty bars with the incoming future quote. Empty bars now carry forward the last observed quote's mid, spread and imbalance with zero OFI, so the feature frame is causal: appending a later quote leaves already-emitted bars unchanged. Regression tests with sparse-timestamp fixtures (quotes at 0s and 30s with different mids; prefix-invariance at both the bar and dataset level). Test count: 52 → 56.

## [v1.2.0] - 2026-10-17
### Added
- 28 market-data replay tests proving the order book stays correct under out-of-order messages, duplicates, dropped messages, disconnects/reconnects, bad snapshots, and extreme activity bursts. Test count: 23 → 51.
- `OrderBook::is_crossed()` detects crossed/locked books (bid >= ask).

### Fixed
- `merge_snapshot` was rejecting valid snapshots, forcing unnecessary re-downloads. Now follows the documented exchange procedure.
- `read_trades` and `read_quotes` no longer panic on parquet files with a missing column or wrong column type. The column helpers return a descriptive error instead, so `analyze` and `export` exit cleanly on corrupt input.
