### Fixed
- Calibration table partition (`src/predict.rs`): `walk_forward_detailed` built the calibration table with `order.chunks(order.len() / 10)`, which fixes a chunk size and lets the bin count fall out of the division, so any scored-row count not divisible by 10 produced an eleventh, nearly empty bin: at 832 scored rows (the archived main session's count) the table was ten bins of 83 rows plus a final bin holding the last 2 rows, whose realized rate is noise from two predictions. The table is now built by rank (`calibration_bins`): with k = min(10, n) bins, bin j takes sorted positions floor(j*n/k) .. floor((j+1)*n/k), so the table always has exactly k nonempty bins, every prediction lands in exactly one bin, and bin sizes differ by at most one row; empty input yields no bins. The sort is unchanged (probability ascending, stable, so ties keep ledger order) and the tuple schema (mean predicted probability, realized rate, row count) is unchanged. This is reporting-only: accuracy, the training-majority baseline, the intervals and the Brier score are computed from the predictions before the partition and do not move, which a new end-to-end fixture pins at the 832-row scale (accuracy, Brier score and a fingerprint of the full prediction vector are asserted identical to the values the pre-fix code produced on the same fixture, while its table goes from 11 bins to 10). Published report artifacts are unchanged; the corrected table applies to future exports. New fixtures: empty input, n = 7 (one row per bin), n = 20 (ten pairs with hand-checked means and rates), n = 832 (exact bin sizes, row conservation, outcome and probability-mass conservation), tied probabilities keeping ledger order, and hand-calculated single-row rates. - Fit-contract alignment for the OFI-price response estimator (`src/speed.rs`, runner in `examples/info_speed.rs`, report in `docs/info_speed_report.json`; the report schema stays `toxicflow.info-speed/v3` and no field is added, removed or renamed). Three defects in the fit machinery are corrected. First, the extended ladder promoted a tau under a weaker contract than the headline ladder: it filled `fit_tau_s` whenever its point fit passed judging and its resample pool was not degenerate, without ever checking the within-draw fits, while the headline ladder additionally requires tau to be bounded by the bootstrap draw fits (the componentwise tau percentile interval strictly inside the search grid and spanning less than a fourfold ratio). The extended ladder now enforces the same promotion contract, with the boundedness check shared by both ladders: an extended fit that passes judging but whose draw-fit tau interval is unbounded reports no tau, and its fit verdict says so in the same terms as the headline failure message. Second, the within-bootstrap-draw fits behind `fit_region` and the bootstrap fit share were unweighted, while the point fit they summarize is covariance-weighted: the draw fits are now produced in a second pass, refit with the weight matrix built once from the draws' covariance (the same construction as the point fit) and held fixed across the draws, falling back to unweighted fits only when that matrix cannot be formed, with the fallback recorded in the report's notes when it happens; the two-component draw fits are unchanged (unweighted, like their point fit). The draw curves themselves are untouched (the refit pass consumes no randomness), so every response point estimate and response interval is unchanged; `fit_region` values and the bootstrap fit share are regenerated under the corrected estimator. Third, the parameter intervals were described as a joint parameter region: `fit_region` holds each parameter's own percentile interval over the draw fits and the boundedness check tests the tau interval only, and the report, README and code now say exactly that (componentwise percentile intervals); the serialized field names are unchanged. Extended-ladder intervals are additionally suppressed on segmented sessions (more than one fully-observed segment), with the reason recorded in the ladder's `resample_pool` block: validation found segmented extended pools of 20 to 50 distinct starts covering at only 0.21-0.50 at 900 s against the 95% nominal level, where single-segment sessions cover 0.92-0.98, so the pool floor is a degeneracy screen rather than a coverage guarantee and interval reporting on that ladder stays off for segmented session structures until the procedure is coverage-validated for them; the point curve, origin counts and pool diagnostics are still published. In the regenerated report the only session with an extended ladder is the main session, whose extended intervals were already suppressed as degenerate, so the visible extended change there is the fit-verdict wording (the pool's recorded suppression reason is unchanged). Under the corrected draw estimator the largest bootstrap fit share across sessions falls from 42% to 17%, and the README figure is updated with it. One validated headline coverage cell is now labelled rather than absorbed: headline bootstrap coverage sits at clean-session levels across the validated grid except the configuration with a planted tau of 30 s and a jump term, read at h = 0 on 3,600-bar gap sessions, which covered at 0.76 against 0.87 on matched clean sessions and a 95% nominal level; the README limitations and the report notes name that configuration as unreliable rather than repaired. New fixtures: an extended point fit that passes judging with an unbounded draw-fit region reports no tau; the stored draw fits are exactly the weighted refits of the collected draw curves on a fixture where weighted and unweighted fits differ; a segmented session with an extended pool above the floor comes out suppressed with the segmented reason, while a clean long session still reports extended intervals and its promoted tau. - Segment-aware bootstrap resampling on sessions with gaps (`src/speed.rs`, runner in `examples/info_speed.rs`, report in `docs/info_speed_report.json`, now schema `toxicflow.info-speed/v3`). The resampling behind the OFI-price response intervals pooled every valid block start in the session and drew uniformly from that pool, which is wrong on segmented sessions in three ways: a fully-observed segment shorter than the drawn block (600 bars on the headline ladder) offered no valid start and never appeared in any resample at all; longer segments were weighted by (length - block + 1) valid starts rather than by their length, tilting the resample universe toward the longest segments' local behaviour and understating sampling variability; and on the extended ladder the pool could collapse to a handful of distinct starts (the published main session's extended ladder had two full-block starts), so the resamples were near-identical repeats and the published extended intervals came out 0.006-0.06 bps wide where the headline intervals are 0.10-0.50 bps wide, still backed by a full resample count in the artifact. Simulation work on sessions with a known response and a main-like gap pattern showed the consequences directly: headline percentile intervals covered at 0.43-0.87 (1-2 h sessions) while the point estimates stayed centred and the HAC intervals covered at their stated level, and segmented sessions passed the bounded-region gate more often than clean sessions of the same length. The resampling is now two-stage and segment-fair: a segment is chosen with weight max(segment length, drawn block length), then a uniform valid start inside it, and a segment shorter than the block is drawn whole; since a draw contributes min(segment length, block) bars, each segment's expected share of the resampled bars is exactly its share of the observed bars. On a single clean segment the scheme reduces to the old one draw for draw (same seed, same stream), so the five captures' published intervals are unchanged value for value; the splice and censoring rules are unchanged, and a max-horizon window still has to lie wholly inside one drawn chunk. Every ladder now reports its resample pool in a `resample_pool` block (drawn block length, distinct block starts in the pool, distinct blocks actually drawn across the resamples, resamples attempted), and a ladder whose pool has fewer than 20 distinct starts is degenerate: its intervals are suppressed (null), its resample count reads 0, no fit is promoted from its draws, and the pool block records the reason. Regenerating the report from the same six recorded sessions under the corrected scheme: every point estimate is unchanged; the main session's headline intervals widen where the fairer resampling says they should (at 300 s, [-0.03, +0.20] becomes [-0.08, +0.18] bps); and the main session's extended ladder is degenerate (seven distinct chunk starts under the corrected counting, below the minimum of 20), so its previously published 900 s and 1500 s intervals (widths 0.061 and 0.063 bps) are withdrawn and the extended intervals are suppressed with the reason recorded, while the extended point curve stands. The simulation harness (`examples/speed_power_sim.rs`) now also records each run's pool size, drawn diversity and degeneracy. Re-running the simulation cells that exposed the defects (same harness, same data-generating seeds and settings: phi = 0.1, 3,600 bars x 100 reps and 7,200 bars x 60 reps, main-like gap and matched clean, all eight planted truths; headline bootstrap 500, sensitivity 100, extended 200) moves headline percentile coverage in gap cells from 0.43-0.76 to 0.76-0.95 at 3,600 bars and from 0.58-0.87 to 0.85-0.95 at 7,200 bars, against matched clean cells at 0.81-0.99 and 0.88-1.00, with the clean-cell values themselves unchanged, as the scheme requires. Bounded-region rates in gap cells fall from up to 0.18 to 0.00 in all but one cell (0.03, two of 60 sessions, matched clean cell 0.00), and the worst gap promotion cell falls from 0.117 to 0.033 (the same cell, tau = 30 s with no jump at 7,200 bars). On the extended ladder, 76% of the 7,200-bar gap sessions are now suppressed as degenerate instead of reporting intervals (before: coverage 0.00-0.17 at 900 s, mean interval width 0.017 bps in the diagnostic cells); the extended sessions that still report, with pools of 20 or more starts, cover at only 0.21-0.50 at 900 s, so the stated minimum of 20 distinct starts is a floor for reporting at all, not a guarantee of coverage on that ladder, and it is left as stated rather than retuned to the simulation outcome. New fixtures: a segmented session whose short segment provably appears in resamples and whose start pool is counted exactly, a single-segment session whose resamples match the old pooled scheme draw for draw under the same seed, and a three-segment session whose extended ladder comes out suppressed with the reason recorded instead of narrow. - Recoverable raw event journal (Stage 3 TF3): a recording session now also writes an append-only journal of the raw market events under `journal/` in the session directory, so a session can be replayed exactly instead of being reconstructed from touch quotes alone. Only events the sync machine commits are journaled: a snapshot record marks each successful merge (the recovery boundary), applied depth updates and recorded trades follow in order, and a failed merge journals nothing. ### Fixed
- Proxy credential disclosure and `https://` proxy acceptance (Stage 3 H2): `net::ProxyConfig::parse` no longer interpolates the supplied URL or any part of it into error messages. A malformed authenticated proxy URL previously echoed the full URL (including `user:pass@`) for a bad scheme, the scheme-stripped remainder for a missing port or host, and the port fragment for a non-numeric port, so a password could reach stderr or logs through the error text; every error now names only the problem class and the expected `http://[user:pass@]host:port` form. `https://` proxy URLs are now rejected with an actionable error (TLS to the proxy is not supported and the CONNECT tunnel is plaintext TCP; use `http://host:port`, since TLS is established to the destination after CONNECT) instead of being silently accepted as plaintext. The supported scheme table is documented on `parse`: `http://` supported, `https://` rejected, anything else rejected.
